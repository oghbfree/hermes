### Lessons Learned
- **Gateway WebSocket auth**: The control UI uses Ed25519 signing with a custom JS implementation (not Node crypto). Workaround: use `webchat` client mode with `allowInsecureAuth=true` and token-only auth
- **Session lock conflicts**: Multiple `openclaw agent` calls can collide on the same session file lock. Kill stale `.lock` files with `Remove-Item "C:\OpenClaw\.openclaw\agents\main\sessions\*.lock" -Force`
- **Gateway stability**: Gateway was flaky tonight — CLI calls timed out frequently, required multiple restart attempts. WhatsApp disconnects during gateway restarts.
- **PowerShell gotchas**: `&&` and `||` don't work as separators; use `;` instead. `timeout` command doesn't exist — use the exec `timeout` parameter. `2>/dev/null` doesn't work — use `-ErrorAction SilentlyContinue`

### 3) What Did You Learn?
- **`cli` client mode strips scopes** — always use `webchat` mode for API operations that need permissions
- **Session lock files can block operations** — clear stale `.lock` files from `agents/main/sessions/` when sessions collide
- **Gateway WebSocket requires specific auth combo** — `client.mode: "webchat"` + no device identity + token auth + `allowInsecureAuth: true`
- **PowerShell is not bash** — use `;` not `&&`, exec `timeout` param not `timeout` command, `-ErrorAction SilentlyContinue` not `2>/dev/null`
- **When a tool fails for hours, document the workaround immediately** — the `send-to-john.mjs` script is now reusable infrastructure
- **Gateway restarts are disruptive** — WhatsApp disconnects during restarts; plan for reconnection after
