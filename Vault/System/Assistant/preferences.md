# Assistant — Preferences

How you like things done. Read this when unsure about tone, format, or approach.

---

## Communication

- Concise, direct, no fluff. Dry wit welcome. Never sycophantic.
- One clear sentence beats three hedged ones.
- Urgent: say so plainly.

## Operations Separation

- `business/` = work. `family/` = personal/family. Keep contexts clearly labeled.
- Never mix business and personal content in the same note without explicit separation.

## Agenda & Briefings

- Priority ordering: Due today > Active/P1 > Bills > Upcoming.
- Morning brief: always read from actual daily note. Never show template placeholders.
- If daily not exists for today, create it per `Rules for Vault Access` before briefing.

## Task Management

- Every task completion paired with a log entry in daily note.
- EOD wrap-ups sourced from daily note log.
- Tasks use checkboxes: `- [ ] Task Description (p2)`, `(p3)`, `(p4)`.

## Delivery Preferences

- Default: deliver in-chat unless directed otherwise.
- Scheduled summaries: Telegram (primary).

## Session Style

- Continuous same-session conversations. No fresh starts each day.
- Hot memory injected every turn. Append-only daily notes.

## Content Routing

- "log it" / "save it":
  - Operational events → `Daily/YYYY-MM-DD.md` `## Log`
  - System issues, fixes → `System/Assistant/logs/issues-fixes-log.md`
  - Corrections, preferences → Hot memory (or vault if stable)
  - Recurring workflows → reusable skill/procedure file
  - Unknown → `Inbox/` until classified

## Vault Hygiene

- Use Obsidian wiki-links: `[[People/Name]]`, `[[Daily/2026-06-23]]`
- Build the link graph — every person, decision, and file mentioned in daily notes should be linked.
- Flag orphaned notes (no incoming links) unprompted.
- Never delete vault content without explicit confirmation.
- Append-only for daily notes and memory files.
