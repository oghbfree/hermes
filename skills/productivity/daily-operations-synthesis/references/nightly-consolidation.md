# Nightly Consolidation Workflow Reference

**Cron job name:** `nightly-consolidation`
**Schedule:** `0 3 * * *` (03:00 UTC+1 daily)
**Job ID:** `3534ca8a8925` (verify via `hermes cron list`)
**Delivery:** Auto-delivered to origin (current chat/topic)

## Purpose

The nightly consolidation is the **file-processing pass** — it reads all cron outputs from the past 24h, updates master intelligence files, consolidates memory, archives old session data, and produces a processing report. It runs at 03:00, after the 22:05 synthesis.

**Distinction from 22:05 synthesis:** The 22:05 `integrated-daily-synthesis` produces the human-facing daily briefing. The 03.00 `nightly-consolidation` does behind-the-scenes file maintenance AND produces a processing report saved to `workspace/DAILY_PROCESSING_REPORT_YYYY-MM-DD.md`. The 03:00 job is NOT silent — it always produces a report.

## Workflow

### 1. Read All Cron Output Files (Past 24h)

```bash
find ~/.hermes/cron/output/ -name "*.md" -newermt "YYYY-MM-DD 03:00" | sort
```

Also read cron session JSON files:
```bash
find ~/.hermes/sessions/ -name "session_cron_*" -newermt "YYYY-MM-DD 03:00" | sort
```

### 2. Parse jobs.json for Execution Summary

Use `execute_code` for reliable parsing (python3 not on MSYS PATH):
```python
import json, os
with open(os.path.expanduser('~/.hermes/cron/jobs.json')) as f:
    data = json.load(f)
jobs = data if isinstance(data, list) else data.get('jobs', [])
enabled = [j for j in jobs if j.get('enabled')]
fired = [j for j in enabled if j.get('last_run_at')]
ok = [j for j in fired if j.get('last_status') == 'ok']
failed = [j for j in fired if j.get('last_status') == 'error']
pending = [j for j in enabled if not j.get('last_run_at')]
print(f"Enabled: {len(enabled)}, Fired: {len(fired)}, OK: {len(ok)}, Failed: {len(failed)}, Pending: {len(pending)}")
```

### 3. Update Master Intelligence Files

Files to update:
- `memories/MEMORY.md` — global memory (compact, focused on durable facts)
- `workspace/memories/MEMORY.md` — workspace memory (more detailed, operational)
- `workspace/memories/USER.md` — user profile (only if user details changed)
- `workspace/memories/insights/INTEGRATED_INSIGHTS_YYYY-MM-DD.md` — full synthesis (if not already generated by 22:05 cron)
- `workspace/memories/security/SECURITY_AUDIT_YYYY-MM-DD.md` — **see security audit persistence note below**

**⚠️ Security audit persistence gap:** The security-policy-check cron writes audit reports to `~/.hermes/memories/security/` (global path) but NOT to `~/.hermes/workspace/memories/security/` (workspace path). The workspace path is where synthesis and consolidation jobs look for audit files. **Always check both paths.** If the audit exists in global but not workspace, copy it to workspace. If the audit wasn't saved at all (check cron output for "Save report to" confirmation), reconstruct it from the cron output file at `~/.hermes/cron/output/73f447bae072/YYYY-MM-DD_*.md` and save to workspace. This has been a recurring gap — the security cron's `write_file` may be blocked by background tool restrictions.

**Note:** The `memory` tool is UNAVAILABLE in cron sessions. Rely on file-based persistence only.

### 4. Consolidate Memory

- Review both MEMORY.md files for staleness
- Merge new intelligence from past 24h sessions
- Remove redundant or outdated entries
- Keep entries compact — memory char limit is 2,200 chars
- Clean up lock files (`MEMORY.md.lock`, `USER.md.lock`) if present

### 5. Archive Old Session Data

- Sessions older than 7 days in `~/.hermes/sessions/` should be archived
- Move to `~/.hermes/sessions/.archive/` (create if needed)
- Archive both interactive `.jsonl` files and `session_cron_*.json` files
- Do NOT archive `sessions.json` or other metadata files

```bash
mkdir -p ~/.hermes/sessions/.archive
find ~/.hermes/sessions/ -maxdepth 1 -name "*.jsonl" ! -newermt "YYYY-MM-DD 03:00" -exec mv {} ~/.hermes/sessions/.archive/ \;
find ~/.hermes/sessions/ -maxdepth 1 -name "session_cron_*" ! -newermt "YYYY-MM-DD 03:00" -exec mv {} ~/.hermes/sessions/.archive/ \;
```

### 6. Write Processing Report

Save to `workspace/DAILY_PROCESSING_REPORT_YYYY-MM-DD.md` covering:
- Sessions processed (counts + key sessions)
- Master intelligence files updated
- Memory consolidation (entries removed/added)
- Archive operations (files archived, active count)
- Issues found (🔴 Critical / 🟡 Warning / ✅ Healthy)
- Priority actions for the day

## Key Patterns

### Session JSONL Structure
Each line in a `.jsonl` session file is a JSON object with `role` field:
- `session_meta` — first line, contains tools and system prompt
- `user` — user messages
- `assistant` — agent responses (may contain `tool_calls`)
- `tool` — tool results

Large sessions (100KB+) should be read with `offset` and `limit` parameters.

### Cron Session JSON Structure
Cron session files (`session_cron_*.json`) contain `session_id`, `model`, `platform: "cron"`, `system_prompt` (truncated), and `tools` (very long — skip). Look at the last few assistant/tool exchanges for the final output.

### DNS Failure Pattern
`httpx.ConnectError: [Errno 11001] getaddrinfo failed` = DNS resolution failure affecting ALL Telegram deliveries at that timestamp. Check if multiple jobs failed simultaneously.

### WhatsApp Dependency
Jobs that send WhatsApp messages fail when WhatsApp is in reconnection loop. Error: `RuntimeError: Connection error` or `WhatsApp channel unavailable`. Expected when WhatsApp is down — report the dependency, not just the error.

## Pitfalls

- **Don't use `memory` tool in cron sessions** — returns "Memory is not available"
- **Don't use `session_search` in cron sessions** — denied for non-whitelisted tools
- **Don't use `python3` in MSYS** — use `execute_code` or venv Python directly
- **Don't re-read full session JSONs** — use `read_file` with offset/limit for large files
- **Don't call `send_message` in cron context** — system auto-delivers final response
- **Two MEMORY.md files exist** — `~/.hermes/memories/MEMORY.md` (global) AND `~/.hermes/workspace/memories/MEMORY.md` (workspace). Update both.
- **Lock files may exist** — clean up `*.lock` files in memories directories after updating
- **AGENTS.md may be blocked** — UTF-8 BOM (U+FEFF) causes warnings on every cron run. Not a security issue but wastes tokens.
